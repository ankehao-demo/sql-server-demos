# SQL Server to PostgreSQL Data Type Mapping

This document provides a comprehensive mapping of SQL Server data types to their PostgreSQL equivalents for the Wide World Importers database migration.

## Numeric Types

| SQL Server Type | PostgreSQL Type | Notes |
|-----------------|-----------------|-------|
| `int` | `integer` | 4-byte signed integer |
| `bigint` | `bigint` | 8-byte signed integer |
| `smallint` | `smallint` | 2-byte signed integer |
| `tinyint` | `smallint` | PostgreSQL has no unsigned types; use smallint |
| `bit` | `boolean` | Convert 0/1 to false/true |
| `decimal(p,s)` | `numeric(p,s)` | Exact numeric with precision and scale |
| `numeric(p,s)` | `numeric(p,s)` | Same as decimal |
| `money` | `numeric(19,4)` | PostgreSQL money type has locale issues |
| `smallmoney` | `numeric(10,4)` | Use numeric for consistency |
| `float` | `double precision` | 8-byte floating point |
| `real` | `real` | 4-byte floating point |

## String Types

| SQL Server Type | PostgreSQL Type | Notes |
|-----------------|-----------------|-------|
| `char(n)` | `char(n)` | Fixed-length character string |
| `varchar(n)` | `varchar(n)` | Variable-length character string |
| `varchar(max)` | `text` | Unlimited length text |
| `nchar(n)` | `char(n)` | PostgreSQL uses UTF-8 by default |
| `nvarchar(n)` | `varchar(n)` | PostgreSQL uses UTF-8 by default |
| `nvarchar(max)` | `text` | Unlimited length text |
| `text` | `text` | Deprecated in SQL Server, use text in PostgreSQL |
| `ntext` | `text` | Deprecated in SQL Server, use text in PostgreSQL |

## Date and Time Types

| SQL Server Type | PostgreSQL Type | Notes |
|-----------------|-----------------|-------|
| `date` | `date` | Date without time |
| `time` | `time` | Time without date |
| `datetime` | `timestamp` | Date and time (less precision) |
| `datetime2` | `timestamp` | Date and time with higher precision |
| `datetime2(7)` | `timestamp(6)` | PostgreSQL max precision is 6 |
| `smalldatetime` | `timestamp(0)` | Date and time with minute precision |
| `datetimeoffset` | `timestamptz` | Date and time with timezone |

## Binary Types

| SQL Server Type | PostgreSQL Type | Notes |
|-----------------|-----------------|-------|
| `binary(n)` | `bytea` | Fixed-length binary |
| `varbinary(n)` | `bytea` | Variable-length binary |
| `varbinary(max)` | `bytea` | Large binary data |
| `image` | `bytea` | Deprecated, use bytea |

## SQL Server-Specific Features

### IDENTITY Columns
SQL Server:
```sql
CustomerID int IDENTITY(1,1) NOT NULL
```

PostgreSQL:
```sql
CustomerID integer GENERATED BY DEFAULT AS IDENTITY
-- or use SERIAL for older PostgreSQL versions
CustomerID serial NOT NULL
```

### Sequences with DEFAULT
SQL Server:
```sql
CustomerID INT DEFAULT (NEXT VALUE FOR [Sequences].[CustomerID]) NOT NULL
```

PostgreSQL:
```sql
CustomerID integer DEFAULT nextval('sequences.customerid') NOT NULL
```

### Computed Columns
SQL Server:
```sql
SearchName AS (concat([PreferredName],N' ',[FullName])) PERSISTED NOT NULL
```

PostgreSQL:
```sql
SearchName varchar(101) GENERATED ALWAYS AS (PreferredName || ' ' || FullName) STORED NOT NULL
```

### JSON Functions
SQL Server:
```sql
OtherLanguages AS (json_query([CustomFields],N'$.OtherLanguages'))
```

PostgreSQL:
```sql
OtherLanguages jsonb GENERATED ALWAYS AS ((CustomFields::jsonb)->'OtherLanguages') STORED
```

## Temporal Table Handling

SQL Server temporal tables use `SYSTEM_VERSIONING` with automatic history tracking. PostgreSQL requires manual implementation using triggers.

SQL Server:
```sql
CREATE TABLE [Sales].[Customers] (
    ...
    [ValidFrom] DATETIME2(7) GENERATED ALWAYS AS ROW START NOT NULL,
    [ValidTo] DATETIME2(7) GENERATED ALWAYS AS ROW END NOT NULL,
    PERIOD FOR SYSTEM_TIME ([ValidFrom], [ValidTo])
)
WITH (SYSTEM_VERSIONING = ON (HISTORY_TABLE=[Sales].[Customers_Archive]));
```

PostgreSQL equivalent requires:
1. Main table with ValidFrom/ValidTo columns
2. History table with same structure
3. Trigger function to maintain history
4. Triggers on INSERT, UPDATE, DELETE

See `07-triggers/temporal_tables.sql` for implementation details.
